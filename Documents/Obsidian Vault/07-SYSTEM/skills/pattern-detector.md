# Skill: pattern-detector (模式检测器)

## Purpose
每月1号运行，读取30天积累的笔记，识别需要大量数据才能看到的结构性模式。

## Trigger
运行命令：`opencode run "执行技能: pattern-detector"`

每月1号早上8AM自动运行

## Process

### 第一步：收集月度数据
- 读取 `01-KNOWLEDGE\` 下过去30天创建/修改的所有笔记
- 读取过去4周的每周综合
- 读取过去4周的信念追踪报告
- 读取 `01-KNOWLEDGE\patterns\` 下已有的模式记录（如果存在）
- 读取 CLAUDE.md

### 第二步：寻找结构性模式

**什么是模式，不是主题：**
- 模式：不同背景下出现的相同结构性动态
- 主题：多个笔记都在讲同一个话题

**要找到的模式类型：**

1. **RECURRENCE（重现）**：同一动态在不同标的/背景下反复出现
   - 例：多个被筛掉的低PE股票后续都大涨 → 说明你的筛选规则可能过于保守

2. **CONVERGENCE（汇聚）**：多个独立来源指向同一结论
   - 例：3个不同渠道的信息都指向同一行业机会

3. **CONTRADICTION（矛盾）**：证据持续积累反对某个信念但尚未触发更新
   - 例：连续多个季度，你的低PE策略都在错过成长股

4. **EMERGENCE（新生）**：某个新出现的事物，前几个月没有
   - 例：开始关注科创板，发现筛选逻辑需要调整

5. **BLIND SPOT（盲点）**：捕捉中反复出现但没有对应permanent笔记的主题
   - 例：反复提到"北向资金"但没有一条permanent笔记

### 第三步：证据要求
- 每个模式至少需要4条来自不同背景的独立笔记证据
- 同一话题的2条笔记不是模式

### 第四步：输出
每个真实模式：
```
# 模式：[模式名称]
日期：[检测日期]

## 类型
[RECURRENCE / CONVERGENCE / CONTRADICTION / EMERGENCE / BLIND SPOT]

## 证据
- [[笔记1]] — [如何证明这个模式]
- [[笔记2]] — [如何证明这个模式]
- [[笔记3]] — [如何证明这个模式]
- [[笔记4]] — [如何证明这个模式]

## 含义
[这个模式对你当前工作或信念意味着什么]

## 建议行动
[具体的、可执行的响应]
```

### 第五步：更新知识库
- 将确认的模式添加到 `01-KNOWLEDGE\patterns\[模式名称].md`
- 如果模式改变了活跃信念或优先级，建议 CLAUDE.md 更新

保存到：`04-JARVIS-OUTPUTS\patterns\[日期]-patterns.md`
